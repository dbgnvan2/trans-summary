## FINDINGS

No medium-or-higher severity findings. Three low/informational notes, none blocking.

### 1. LOW (informational) — P23 — one-draw calibration on held-out drafts

JS6 part d and the WO6 prompt comparison judge each held-out draft with one judge run
and one draft per slot. The calibration report flags this itself ("Each run made one
draft per slot, so part of the drop can be run-to-run variation"), and the drift
monitor's gold detection runs `--repeats 3`, so the recurring armed surface is N≥3.
The one-shot draft counts (9 flags vs 22; 93% vs 97%) are directional, not locked.

- Risk: low. These numbers are read as a trend, not as a regression bar, and the report
  says so. No gate or test asserts on the single-draw numbers.
- No action required; if the WO6 comparison is ever cited as proof the prompt fixed
  outside facts, re-run it N≥3.

### 2. LOW (informational) — P33 — the severity step's remaining effect post-WO

Since WO2 made faithfulness warn-only, the severity step no longer gates publication at
all. Its two remaining load-bearing effects are (a) the wrong / not-quite-right label in
the warning, and (b) which flagged claims generation revises (WRONG revised; NOT QUITE
RIGHT kept as written, JS0.d). JS6 measured the step downgrading 0 of 12 hand-labelled
NOT QUITE RIGHT flags (first WRONG vote final + "if unsure, answer WRONG" → 22/22 first
votes WRONG). In practice it labels nearly every flag WRONG, so generation revises
everything flagged, as before WO.

- Risk: low. This is the P33 outcome already recorded in `LEARNINGS.md`, and the report
  states it plainly. The step now spends 1–3 extra LLM calls per flag to decide a warning
  label + revision scope. It is honest, but the cost/benefit of keeping
  `FAITHFULNESS_SEVERITY_MODE = "majority3"` (vs "off") is worth revisiting later.

### 3. LOW (informational) — P7 — no-outside-facts rule is partial, and nothing blocks

The WO1 prompt rule cut outside facts from 10 to 4 in WO6 but did not remove them (the
first name "Marta Bertolaso" still appears in 3 of 12 new drafts). Because faithfulness
now warns and never blocks, an added age, spelled-out abbreviation or first name that
the entity check does not reach reaches published prose with only a warning.

- Risk: low. This is the explicit, user-approved WO decision ("warn only, never block")
  and is documented in `docs/plan_warn_only_2026-10-19.md` (WO6 table). The entity check
  still blocks wholly-absent multi-word names. Not a defect; a residual to watch in live
  runs.

## CHECKED (per pattern checklist)

- Single-source-of-truth (pitfall 2 / P19): the cache key folds in the actual source of
  `classify_severity`, `judge_severity`, `_parse_severity_response`, `_evidence_in_source`
  (via `_judge_input_functions`), `FaithfulnessResult` (which claims fail), the
  `_SEVERITY_TYPES` constant, the severity prompt text (read from the file at call time),
  and the three evidence thresholds. No parallel hand-copied list — a change to any of
  these re-keys the cache, verified by `test_js3a_*`.
- Fail-closed on transient failure (P1): a FAIL resting only on `severity_undecided`
  claims is neither cached in memory nor flagged on disk, so the next run re-asks
  (`test_js1d_undecided_fail_is_not_cached_or_flagged`); a decided WRONG FAIL keeps the
  D2 two-PASS marker (`test_js1d_decided_fail_still_cached_and_flagged`). A severity
  reply that won't parse after `JUDGE_PARSE_ATTEMPTS` stays WRONG, never a pass
  (`test_js1d_parse_error_keeps_wrong`).
- Evidence check (P6/P7): a NOT QUITE RIGHT vote counts only when every "..."/ellipsis
  part of ≥2 words is in the folded source, a run of ≥4 words is present, and the quote
  shares a significant word with the claim. Adversarial cases pinned: invented evidence,
  an invented short tail, an unrelated-but-real quote (`test_js1c_*`).
- Dirty state (P8): a PASS cached under one severity mode is not served under another
  (`test_js3b_old_cached_pass_not_served`); a PASS with NOT QUITE RIGHT claims is replayed
  with those claims (`test_js3b_warn_replayed_with_claims`); a cached PASS keeps its claim
  count so the % score survives a fresh process (`test_wo3_cached_pass_keeps_its_claim_count`).
- Return-contract change (P22): `check_faithfulness` now returns WARN (never FAIL).
  Every production caller re-checked and updated: `_faithfulness_precheck` and
  `_abstract_gate_precheck` read flagged claims from `items`, not from a FAIL status;
  `blog_ungrounded_claims` branches on its own string status, which is preserved;
  `check_entity_grounding` gained a `suffixes` param that is actually honoured in its loop
  and every caller passes it. No stale `faithfulness … FAIL` branch remains in production.
- Front-end wiring (P25): the GUI's incomplete-source notice is asserted to reach the
  Confirm dialog and the run log before the first stage (`test_it2b`, `test_it2c`); the
  `run_gate` warning lines flow through the GUI's own logger exactly once and the GUI's
  duplicate WARN loop was removed (`test_wo5_gui_log_shows_flagged_claims_once`).
- Exact assertions, not floors (P29): the new tests assert `==` on claim counts, scores
  (80%, 100%), missing-range tuples, vote sequences and item dicts. The one `>=` is a
  version-string monotonicity check (`JUDGE_LOGIC_VERSION`), which is correct use.
- Test validity (P27/P10): every new test contains a real assert and is
  mutation-style — the cache-rekey tests patch the very thing under test and assert the
  key changes; the vote tests script a fake judge and assert exact vote counts/order; the
  adversarial evidence tests show the input passes without the check. No vacuous tests.
- Test isolation (P28/P34): the new tests monkeypatch `config.PROJECTS_DIR`/`LOGS_DIR` to
  `tmp_path` and stub the judge/API path; the GUI tests build `TranscriptProcessorGUI`
  via `__new__` (no constructor side effects) and stub `stage_runners`. `conftest.py`
  sets `FAITHFULNESS_SEVERITY_MODE = "off"` in the offline fixture so the offline suite
  never reaches a live severity call, and the severity tests opt back in with their own
  monkeypatch.
- Calibration honesty (P20/P33): `docs/calibration_judge_severity_2026-10-19.md` states
  the step's near-zero downgrade rate, the drafts-failing count before/after, and the
  single-draw caveat, and `docs/plan_judge_severity_2026-10-19.md` records six prior
  review fixes (F1-F6) plus "adjacent issues found, not fixed". Prompt examples are
  tested for overlap with the gold set, the review's 43 claims and prose_real sentences
  (`test_js4b_*`), so the policy is not fitted to the measured claims.
